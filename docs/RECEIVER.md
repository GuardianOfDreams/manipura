# Manipura — Receiver (для 413a: Mac/PC, приём и распознавание)

> Этот документ — для чата 413a, который строит **принимающую сторону**.
> Manipura (iPhone, Telegram Mini App) → **аудио** → Mac/PC → **анализ** → **MIDI/OSC/gamepad**.

## 1. Что Manipura отдаёт в эфир (факт)

**Один монофонический аудиопоток** (не данные, не Bluetooth, не WebSocket). Через:

- **AirPods** (Bluetooth, но это звук, не BLE GATT)
- **Динамик iPhone** (в воздух)
- **Провод** (Lightning → USB-C, 3.5 mm через переходник)

**Сигнал:**

- 48 000 Hz, mono, 32-bit float (в Web Audio)
- На выходе — либо цифровой (AirPods, провод), либо аналоговый (динамик)
- **Формат:** смесь 5 голосов (A, O, U, E + F0 sine 100 Hz) с весами `{A, O, U, E, C}`, сумма = 1.0

## 2. Что именно звучит (спектрально)

Каждая гласная — **набор 64 гармоник** от F0 = 100 Hz (шаг 100 Hz: H1=100, H2=200, …, H64=6400).

**STD-пресеты** (гауссовы форманты):

| Гласная | F1 | F2 | F3 | Примечание |
|---|---|---|---|---|
| A | 700 | 1200 | 2500 | Стабильна |
| O | 440 | 750 | 2160 | Тёмная |
| U | 300 (H3) | 700 (H7-H8) | — | Ручной массив, хвост до H40 обрезан |
| E | 410 | 2000 | 2570 | Светлая |

**Центр C** — чистая синусоида 100 Hz (только H1, остальные нули).

**Веса:** если наклон влево — доминирует A (например, A=0.5, C=0.5). Если диагональ — A=0.5, U=0.5. Сумма всегда 1.0.

## 3. Задача приёмника (413a)

```
[Микрофон / линейный вход Mac/PC]
        │
        ▼
[FFT или LPC]
        │ F1, F2, F3 (Гц)
        ▼
[TunerClassifier]   ← эталоны из docs/TUNER.md
        │ r1 = ln(F2/F1), r2 = ln(F3/F2)
        │ → {A, O, U, Y, I, E} вероятности
        ▼
[Маппинг]
        │ 4 канала: A, O, U, E (+ F0, громкость, всего 8)
        ▼
[MIDI CC] → виртуальный джойстик (FlexInput Windows / OJD macOS)
```

## 4. Эталоны (r1/r2) — из PRISM

**TunerClassifier** использует инварианты `r1 = ln(F2/F1)`, `r2 = ln(F3/F2)` (подробности — `prism/docs/TUNER.md`).

| Гласная | r1 | r2 | std r1 | std r2 |
|---|---|---|---|---|
| A | 0.551 | 0.755 | 0.145 | 0.079 |
| O | 0.560 | 1.197 | 0.088 | 0.190 |
| U (тёмная) | 0.66 | 1.20 | — | — |
| U (светлая) | 1.70 | 0.70 | — | — |
| Y | 1.623 | 0.355 | 0.159 | 0.132 |
| I | 2.084 | 0.293 | 0.108 | 0.069 |
| E | 1.292 | 0.312 | 0.175 | 0.047 |

**Manipura использует только A, O, U, E** (4 гласные). Y/I — в эталонах есть, но UI их не рендерит.

**У двуликая** — в Manipura берётся **тёмная** версия (r1=0.66, r2=1.20), потому что STD U-пресет в движке соответствует ей.

## 5. Что принимать (сигнал vs смесь)

**Проблема:** Manipura выдаёт **смесь** гласных, а не одну.
- Центр → только F0 (нет формант) → классификатор должен сказать «C» или «no vowel»
- Лево → A=1.0 → классификатор скажет A
- Лево+вперёд диагональ → A=0.5, U=0.5 → **смесь**, классификатор увидит промежуточные r1/r2

**Это by design.** Manipura отдаёт **позицию в 2D-кресте**, а не дискретную гласную. Приёмник может:

1. **Показывать доминирующую** (argmax по 6 гласным)
2. **Показывать веса** (например, через смесь цветов — `ColorMixer` в PRISM)
3. **Управлять осями** (X → A/E, Y → U/O)

**Рекомендация для 413a:** приёмник отдаёт **4 непрерывных канала** (A, O, U, E) через **4 MIDI CC**:

| CC | Ось | Что управляет (дрон) |
|---|---|---|
| CC1 | A (left) | roll |
| CC2 | E (right) | roll (инверс) |
| CC3 | U (front) | pitch |
| CC4 | O (back) | pitch (инверс) |

**Или** проще: `X = A - E` (лево/право), `Y = U - O` (перед/назад). 2 канала. Но тогда теряется морфинг.

**Решение — за Александром (413).** Manipura отдаёт «сырьё», приёмник решает.

## 6. F0 и громкость

- **F0 = 100 Hz** (жёстко в текущей версии). У приёмника `detectPitch` (PRISM) должен найти 100 Hz.
- **Громкость** — по RMS. Зависит от `masterGain = 0.5` в Manipura, нормализовано до пика 0.9 на буфер.

## 7. Точки сопряжения (API)

### Со стороны Manipura (что уже есть)

- `manipura.wasm` — движок (`docs/ENGINE.md`)
- `js/audio.js` — смесь (`docs/AUDIO.md`), `weightsFromIMU(beta, gamma)`
- **Наружу — только звук.** Manipura **не** отправляет данные в сеть. Это сознательно: обход Web Bluetooth iOS.

### Со стороны 413a (что нужно)

1. **Захват звука** (`juce::AudioDeviceManager`, `Continuity Camera` / `BlackHole` / провод)
2. **LPC** (или FFT + пики) → F1, F2, F3 → r1, r2
3. **TunerClassifier** (порт из `prism/core/TunerClassifier.h`)
4. **Маппинг** `r1, r2` → `{A, O, U, E}` (4 веса, сумма 1.0)
5. **MIDI CC** — виртуальный порт `juce::MidiOutput::createNewDevice`

### Формат MIDI-сообщений (предложение)

```
CC1 = A (0..127)   # лево/право
CC2 = E (0..127)   # право/лево
CC3 = U (0..127)   # перед/назад
CC4 = O (0..127)   # назад/перед
CC5 = F0 (0..127)  # 100 Hz -> нормализовано
CC6 = RMS (0..127) # громкость
```

Частота отправки — 30..60 Гц (по IMU). Без сглаживания на приёмнике (Manipura уже сглаживает 20 мс).

## 8. Калибровка

Проверить, что `F0=100` совпадает с iPhone. AirPods могут добавить задержку (~150 мс) и DSP-обработку — проверить на слух и спектрограммой.

**Если AirPods вносят искажения:** использовать провод или динамик + микрофон. AirPods — компромисс между удобством и точностью.

## 9. Что НЕ передаётся

- **Не** WebSocket (нет сервера)
- **Не** Bluetooth GATT (iOS блокирует)
- **Не** MIDI напрямую с телефона (Web MIDI на iOS ограничен)
- **Не** OSC

Только **звук**. Это ключевое архитектурное решение (см. `prism/docs/MANIPURA.md`, M.1).
